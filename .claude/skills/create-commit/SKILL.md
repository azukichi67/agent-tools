# 変更を 1コミット1目的に分けてコミットする

ブランチの作成・品質チェック（テスト・lint・型チェック）・push は扱わない。コマンドは全てリポジトリ直下（`git rev-parse --show-toplevel`）で実行する。作業用のファイル（patch・メッセージ）は `$(git rev-parse --git-dir)/create-commit/` に置く。git に追跡されず、作業ツリーの変更と混ざらないため。

## 手順

### 1. 前提を確かめる

- 現在のブランチが `main` なら、終了してブランチを切るよう伝える。
- `git status --porcelain` が空なら、コミットする変更が無いと伝えて終了する。
- `git rev-parse HEAD` で開始時のコミットを控える。

### 2. 変更を読む

staged・unstaged・untracked を区別せず、全てを対象にする。`git add -N .` で untracked のファイルを差分に出し、`git diff HEAD` を読む。

### 3. 分割する

1コミット1目的に分ける。目的の単位は、表題を「〜と〜」で繋がずに1文で書けること。

- 1ファイルに複数の目的が混ざっていれば、ハンク単位で分ける。
- 依存される変更を先のコミットにする。
- 意図しない変更に見えるもの（デバッグ出力・一時ファイル・`.env` などの秘密情報）は、どのコミットにも入れず「対象外」にする。

### 4. メッセージを書く

表題は `<type>: <何をするか（日本語）>`（例: `feat: 場所の登録画面を追加する`）。

| type | 使う変更 |
|---|---|
| `feat` | 機能の追加・変更 |
| `fix` | 不具合の修正 |
| `refactor` | 振る舞いを変えないコードの整理 |
| `perf` | 性能の改善 |
| `test` | テストだけの追加・修正 |
| `docs` | ドキュメントだけの変更 |
| `style` | フォーマットなど、意味を変えない見た目の変更 |
| `build` | ビルド・依存パッケージの変更 |
| `ci` | CI 設定の変更 |
| `chore` | 上のどれにも当たらない雑務 |

表題と本文に何を書くかは、`code-comments` Skill（`.claude/skills/code-comments/SKILL.md`）の「コミットログ・PR（Why）」に従う。

### 5. コミットする

手順3で決めた順に、コミットごとに次を行う。

1. `git reset -q` でインデックスを空にし、`git add -N .` で untracked のファイルを差分に出し直す。
2. このコミットの変更をインデックスに入れる。
   - ファイル全体を入れる: `git add -- <ファイル>`
   - ファイルの一部を入れる: `git diff -- <ファイル>` を patch に書き出し、このコミットに入れない部分を消して `git apply --cached <patch>` する。`git add -p` は対話的で使えない。patch はコミットごとにその時点の差分から作り直す（前のコミットで差分が変わるため）。
     - ハンクごと除く: そのハンクを消す。
     - ハンクの一部を除く: 入れない `+` 行を消し、入れない `-` 行は先頭を空白にして文脈行に変え、`@@ -a,b +c,d @@` の行数 `b`・`d` を数え直す。
3. `git diff --cached --stat` と `git diff --cached` が、手順3で決めたこのコミットの範囲どおりであることを確かめる。
4. メッセージをファイルに書き、`git commit -F <ファイル>` する。

pre-commit hook で失敗したら、hook が指摘した問題を直してから、同じコミットをやり直す。

### 6. 確かめて報告する

- `git reset -q` で、残った intent-to-add を外す。
- `git status --porcelain` に、対象外にしたものだけが残っていることを確かめる。
- `rm -rf "$(git rev-parse --git-dir)/create-commit"` で作業用のファイルを消す。
- `git log --oneline <控えたコミット>..HEAD` と、対象外にしたもの（理由付き）を報告する。
