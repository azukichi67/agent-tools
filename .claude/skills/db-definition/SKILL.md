# DB の定義の仕方

DB の名前は、アプリのコード・SQL・マイグレーションのどこからも参照され、後から変えるのが難しい。名前と共通のカラムの持ち方がテーブルごとに違うと、JOIN の条件や参照先を取り違え、日時の比較でずれが起きる。

## このスキルが決める範囲

- 決めるのは、テーブル・カラム・ビュー・Enum の名前と型、全テーブルに共通するカラム、マイグレーションの名前と中身の置き方に限る。正規化やインデックスの設計は扱わない。
- ORM がコード側の名前（PascalCase・camelCase など）を別に持つ場合も、このスキルが決めるのは DB 側の名前である。
- **これから作る定義が対象。** 既存のテーブルやカラムは、改名が依頼に含まれるときだけ変える。

## 定義する手順

1. 作る・変えるテーブル・カラム・ビュー・Enum を書き出す。
2. DB が PostgreSQL なら `references/postgresql.md` を読む。
3. 規則に沿って定義し、マイグレーションを作る。
4. 「書き終えたら確かめること」を全て満たすまで直す。

## 規則

### 1. テーブル名は複数形、カラム名は単数形の snake_case にする

| 対象 | 単数/複数 | 例 |
|---|---|---|
| テーブル | 複数形 | `transport_operations` |
| カラム | 単数形 | `car_type` |
| ビュー | 複数形 ＋ `_view` | `transport_operations_view` |

### 2. テーブル名から分かる部分をカラム名から省く

`users` テーブルのユーザー名は `name` にする。`user_name` にしない。

### 3. 主キーは `<テーブル名の単数形>_id` にする

`users` テーブルの主キーは `user_id` にする。`id` にしない。

主キーと、それを参照する外部キーが同じ名前になるので、JOIN で `USING` を使え、どのテーブルの ID かを取り違えにくい。規則2の例外である。

### 4. 真偽値のカラムは `code-naming` の形を snake_case にする

`code-naming` Skill（`.claude/skills/code-naming/SKILL.md`）の規則4に従い、`if` の条件に置いて英文になる名前にする。書式だけ snake_case にする（`is_published` / `has_paid` / `can_edit`）。

### 5. 日時のカラムはタイムゾーン付きの型にする

タイムゾーンを持たない型では、書き込んだ側と読み出す側のタイムゾーンが違うときに時刻がずれる。

### 6. 作成日時と更新日時を持たせる

| 論理名 | 物理名 | 型 | デフォルト |
|---|---|---|---|
| 作成日時 | `created_at` | タイムゾーン付きの日時 | DB の現在時刻 |
| 更新日時 | `updated_at` | タイムゾーン付きの日時 | DB の現在時刻 |

- `created_at` は全てのテーブルに持たせる。
- `updated_at` は、行が更新されうるテーブルにだけ持たせる。
- 行を UPDATE するときは、`updated_at` も現在時刻に更新する。更新の手段（ORM の機能・トリガー・アプリのコード）はプロジェクトに合わせる。

### 7. Enum 型は `enum_` を付けた snake_case、値は大文字の snake_case にする

型名は `enum_car_type`、値は `SMALL_TRUCK` のようにする。

### 8. マイグレーションには内容が分かる snake_case の名前を付ける

- 名前を読めば、何のための変更かが分かるようにする（`add_car_type_to_transport_operations`）。
- 既存のデータの変更が要るときは、そのクエリをスキーマを変えたのと同じマイグレーションに書く。

## 書き終えたら確かめること

- [ ] テーブル名とビュー名が複数形、カラム名が単数形で、全て snake_case になっている
- [ ] ビュー名が `_view` で終わっている
- [ ] カラム名に、テーブル名から分かる部分が重ねて入っていない
- [ ] 主キーが `<テーブル名の単数形>_id` になっている
- [ ] 真偽値のカラムを `if` の条件に置いて、英文として読める
- [ ] 日時のカラムがタイムゾーン付きの型になっている
- [ ] 全てのテーブルに `created_at` があり、更新されうるテーブルに `updated_at` がある
- [ ] UPDATE のときに `updated_at` が更新される
- [ ] Enum 型の名前が `enum_` で始まり、値が大文字の snake_case になっている
- [ ] マイグレーションの名前から変更の内容が分かる
