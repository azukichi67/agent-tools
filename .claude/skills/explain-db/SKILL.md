# DB 全体の解説資料を作る

DB 全体を理解するための資料一式を作る。中身は次の3種類。

| ファイル | 作り方 | 役割 |
|---|---|---|
| `er.html` | `create-er` | 全体の構造。テーブルから個別ページへ飛べる |
| `tables/<テーブル名>.html` | `explain-table` | テーブルごとの動き |
| `index.html` | このスキル | 入口。グループごとの役割と、グループをまたぐデータの流れ |

全て `git rev-parse --show-toplevel` の直下の `.db-docs/<DB名>/` に置く。以下のパスは全てこのトップからの相対パス。

- 索引ページのテンプレート: `${CLAUDE_SKILL_DIR}/../explain-table/assets/template.html`
- ER 図の組み立てスクリプト: `${CLAUDE_SKILL_DIR}/../create-er/scripts/build.mjs`

`${CLAUDE_SKILL_DIR}` が展開されない環境では、この SKILL.md があるディレクトリに読み替える。

## 手順

### 1. 入力を確かめる

$ARGUMENTS から次を取る。

- tbls の出力ディレクトリ（必須）
- アプリのリポジトリのパス（必須）
- 対象グループ名（任意。省略時は全グループ）

必須のものが足りなければユーザーに聞く。

### 2. ER 図を作る

Skill tool で `create-er` を呼び、args に tbls の出力ディレクトリを渡す。グループ分けは `.db-docs/<DB名>/er-meta.json` に残る。

### 3. 対象テーブルを決める

対象グループに属するテーブルを、`er-meta.json` から集める。

**30 テーブルを超える場合は、作り始める前にユーザーに範囲を確認する。** テーブル1つごとにソースを読むため、時間がかかる。

### 4. テーブルごとの解説を作る

テーブル1つにつき、サブエージェントを1つ起動する。1つのサブエージェントには1テーブルだけを任せる。同時に起動するのは 5 つまでにする。

サブエージェントへの依頼:

```
Skill tool で explain-table を実行せよ。args は「<tbls の出力ディレクトリ> <テーブル名> <アプリのリポジトリのパス>」。
終わったら、次の4つだけを返せ。
1. 生成した HTML のパス
2. 「一言でいうと」の文
3. このテーブルに行が増えるきっかけになる操作（画面名・API 名）と、その根拠の file:line
4. その操作で一緒に書き込まれる他のテーブル
```

**完了の条件**: 対象テーブルの全てについて、HTML ができたか、失敗した理由が記録されていること。

### 5. ER 図から個別ページへ飛べるようにする

`er-meta.json` の `detailLinks` に、HTML ができたテーブルを `"<テーブル名>": "tables/<テーブル名>.html"` の形で足す。そのうえで ER 図を組み立て直す。

```bash
node ${CLAUDE_SKILL_DIR}/../create-er/scripts/build.mjs <schema.json> .db-docs/<DB名>/er-meta.json .db-docs/<DB名>/er.html
```

`<schema.json>` は、create-er が使ったものと同じにする。入力ディレクトリにあればそれ、無ければ `.db-docs/<DB名>/schema.json`。

### 6. グループをまたぐ流れをまとめる

手順4で返ってきた「きっかけになる操作」と「一緒に書き込まれるテーブル」を、操作ごとにまとめる。複数のグループのテーブルに書き込む操作が、グループをまたぐデータの流れになる。

- 流れの根拠は、サブエージェントが返した `file:line` にする
- 返ってきた情報だけでつながりが分からない箇所は、ソースを読んで確かめる。確かめられなければ「推測」と明示する

### 7. 索引ページを作る

テンプレートをコピーし、`{{TITLE}}` と `{{BODY}}` を置き換えて `.db-docs/<DB名>/index.html` に出力する。スタイルを書き足さない。

ページの並び:

| 節 | 内容 | 使う部品 |
|---|---|---|
| 冒頭 | この DB が何を記録するかを1〜2文で。`er.html` へのリンク | `.tldr` |
| 01 グループ | グループごとに、名前・役割・テーブル数 | `table` |
| 02 データの流れ | 手順6でまとめた、グループをまたぐ操作。操作ごとに、書き込まれるテーブルを順に並べる | `.flow` / `.step` |
| 03 テーブル一覧 | グループごとの表。テーブル名（個別ページへのリンク）と「一言でいうと」 | `table` |
| 04 作れなかったテーブル | 失敗したテーブルと理由。無ければ省く | `.box.warn` |

グループが AI による分類（`source` が `ai`）なら、01 にそう明記する。

### 8. 報告する

`index.html` のパスを報告し、ホストのブラウザで開くよう伝える。開いたら崩れていないか、リンクが切れていないかを見てもらう。

作れなかったテーブルがあれば、その一覧も報告する。
