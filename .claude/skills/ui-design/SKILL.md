# UI デザインの原則

画面は、作った人の頭の中を知らない人が、説明を読まずに使うものである。押せるかどうか、今どこにいるか、何が起きたかが画面から読み取れないと、ユーザーは迷い、誤操作し、問い合わせる。原則に照らして決めておけば、見た目の好みではなく理由で画面を決められる。

## このスキルが決める範囲

- 決めるのは画面の構成・文言・部品の選び方・動きに限る。色・フォント・余白の値は、プロジェクトのデザイントークンや既存の画面に合わせる。
- 対象は Web の画面で、PC とモバイルの両方を含む。モバイル幅でだけ効く原則は、各ファイルに条件として書いてある。
- これから作る画面と、変更する部分が対象。頼まれていない既存の画面は、レビューを頼まれたときだけ扱う。

## 画面を決める手順

1. **画面に含まれる要素を書き出す。** 状態ごと（0件のとき・エラーのとき・処理中のとき）の画面も含める。
2. **`references/text.md` と `references/layout.md` を読む。** 文言と配置はどの画面にもある。
3. **書き出した要素に対応するファイルを読む。**

   | 画面にあるもの | 読むファイル |
   |---|---|
   | ボタン・リンク・チェックボックス・ラジオボタン・トグル・タップする要素 | `references/components.md` |
   | 入力フォーム | `references/forms.md` |
   | 複数の画面・メニュー・階層・戻る／進む | `references/navigation.md` |
   | ドラッグ・ジェスチャ・アニメーション・時間のかかる処理 | `references/interaction.md` |
   | 確認ダイアログ・モーダル・完了の通知・長い手続き・初期設定 | `references/confirmation.md` |
   | 状態・数値・日時・アイコン・スクロールする一覧 | `references/information.md` |

4. **読んだ原則ごとに、画面が沿っているかを決める。** 沿わせない原則があれば、理由を書き残す。

書き出した要素の全てについて、対応する原則に沿うか、沿わせない理由が決まったら終わり。

## 規則

個々の原則は `references/` にある。ここには、カテゴリをまたいで判断が分かれるときの決め方だけを置く。

### 1. 確認より取り消しを用意する

誤操作は、事前の確認で防ぐより、後から戻せるようにするほうがよい（G-2）。毎回の確認は読まれずに押されるようになり、防ぐ力を失う。

- 取り消せる操作は、確認せずにすぐ実行する（G-3）。取り消しの手段（Undo・ゴミ箱・送信の取り消し）を用意する。
- 確認ダイアログは、取り消せない操作（完全な削除・課金・外部への送信）にだけ出す。ボタンには実行される動詞を書く（A-4）。

### 2. 完了の通知は、画面の変化で結果が見えないときだけ出す

G-3（正常完了を報告しない）と D-5（操作の近くでフィードバックする）は、次のように使い分ける。

- 操作の結果が画面にそのまま現れる（行が消える・トグルが切り替わる・一覧に増える）なら、通知は出さない。
- 結果が画面に現れない（裏で保存した・メールを送った）なら、操作した場所の近くに短く知らせる（ボタン自体の表示の変化・すぐ横のトースト）。
- 失敗は必ず知らせる。知らせ方は A-5 に従う。

### 3. モーダルにするのは、答えないと先に進めないときだけにする

F-6（UI をロックしない）とモーダルの作法は、次のように使い分ける。

- 答えないと先に進めない問い（規則1の取り消せない操作の確認など）だけをモーダルにする。それ以外の入力や情報は、インライン・横のパネル・トーストにし、背景の操作を続けられるようにする。
- モーダルにしたら、背景は操作させず、フォーカスをモーダルの中に留める。閉じるボタンと ESC キーで抜けられるようにする（E-2）。
- 時間のかかる処理は、モーダルで画面を塞がず、処理中も他の操作とキャンセルをできるようにする（F-6）。

## 書き終えたら確かめること

- [ ] 0件・エラー・処理中・長い文字列のときの画面も、原則に照らした
- [ ] 書き出した要素に対応する `references/` のファイルを全て読んだ
- [ ] 沿わせない原則があれば、その理由が残っている
- [ ] 確認ダイアログが、取り消せない操作にだけ出ている
- [ ] モバイル幅で表示して、タップする要素の大きさと一度に見せる量を確かめた
- [ ] グレースケールにしても、状態や区別が伝わる

## 参照ファイル

- `references/text.md` — ラベル・ボタン・メッセージ・エラーの文言（A-1〜A-5）
- `references/components.md` — ボタン・リンク・選択部品・トグルの見せ方と大きさ（B-1〜B-7）
- `references/forms.md` — 入力項目の持ち方・部品の選び方・入力の揺れの吸収（C-1〜C-8）
- `references/layout.md` — グループ分け・項目の順序・ツールとフィードバックの位置・色とフォントの数・揃え（D-1〜D-7）
- `references/navigation.md` — 現在地・戻り道・メニューの順序・遷移の向き・モバイルの階層（E-1〜E-6）
- `references/interaction.md` — 直接操作・アニメーション・反応の速さ・UI をロックしない（F-1〜F-6）
- `references/confirmation.md` — 前提条件の提示・取り消し・確認と通知・決定の先送り・高度な機能の隠し方（G-1〜G-5）
- `references/information.md` — 状態の表示・数値の意味・アイコンと文字・スクロールの示唆・プレビュー・色に頼らない区別（H-1〜H-6）
