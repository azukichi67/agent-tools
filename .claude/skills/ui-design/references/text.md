# 文言（A）

ラベル・ボタン・メッセージ・エラーに書く言葉。

## A-1 ユーザーの言葉を使う

- システム内部の用語や業界の略語ではなく、ユーザーが普段使う言葉で書く。
- 英語の UI 用語は母語に訳す。
- 例:
  - 「ファイルをアップロード」→「写真を送る」
  - 「リクエストがタイムアウトしました」→「接続に時間がかかっています。しばらくお待ちください」
  - 「ID」→「会員番号」
  - 「MTG 設定」→「会議を設定」
  - 「Submit / Cancel」→「送信 / キャンセル」

## A-2 ナビゲーションの項目は名詞にする

- 情報の種類ごとに画面を作り、メニューやタブの項目はその情報の名前（名詞）にする。行為（動詞）にすると、どこへ行くのかが分からない。
- 名詞は短くする。「〜を確認する」のような説明文にしない。
- 例: 「商品を探す / 注文する / 設定を変更する」→「商品一覧 / 注文履歴 / 設定」

## A-3 選択肢の文言は肯定文にする

- チェックボックスやトグルのラベルは「〜する」と書く。「〜しない」だと、チェックを入れる操作が「しないことを選ぶ」になり、読み違える。
- 選んだ結果が分かる具体的な文にする。
- 例:
  - 「メール通知を受け取らない」→「メール通知を受け取る」
  - 「自動保存を無効にしない」→「自動保存を有効にする」
  - 「オプションを適用」→「週次レポートを受け取る」

## A-4 ボタンには実行される動詞を書く

- 「OK」「はい」「実行」「確定」ではなく、押すと起きること（「保存する」「削除する」「注文を確定する」）を書く。
- 否定側のボタンも、何をしないのかを書く（「保存しない」）。
- ダイアログごとに文言を変える。どれも「OK」だと、ログアウトと削除を取り違える。

## A-5 エラーは、何が起きたかと次にすることを書く

- 起きたことを1文、ユーザーが次にすることを1文で書く。
- ユーザーを責める書き方（「入力が間違っています」）ではなく、満たす条件（「8文字以上で入力してください」）を書く。
- エラーコードや技術的なメッセージだけを出さない。必要なら、説明の後に添える。
- 例:
  - 「エラーが発生しました」→「接続できませんでした。インターネット接続を確かめて、もう一度お試しください」
  - 「入力が無効です」→「メールアドレスの形式が正しくありません。例: name@example.com」
  - 「Error 500」→「サーバーに接続できません。しばらくしてからお試しください」
- 表示する位置は D-5 に従う。
