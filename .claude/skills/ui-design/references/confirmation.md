# 確認と手続き（G）

前提条件の示し方・確認と取り消し・決定を求めるタイミング・高度な機能の見せ方。確認と通知をどこまで出すかは SKILL.md の規則1・2で決める。

## G-1 前提条件は始める前に示す

- 手続きに要るもの（書類・ログイン・対象者の条件）を、手続きの最初に一覧で示す。途中や最後になって求めない。
- 例:
  - カートに入れた後でログインを求める → 購入に進む前にログインかゲスト購入かを選ばせる
  - 提出した後で書類の不足を伝える → 始める前に必要な書類の一覧を出す

## G-2 誤操作を防ぐより、誤操作しても戻せるようにする

- 全ての操作が取り消せれば、誤操作は実質的に無くなる。
- 例:
  - 削除のたびに確認する → すぐ削除し、Undo で戻せるようにする
  - 削除したものを30日間は復元できるようにする
  - 送信の前に必ずプレビューさせる → 送信後の数秒間は取り消せるようにする

## G-3 確認も完了の報告もせずに実行する

- ユーザーがしようとしたことを、いちいち確認せずに実行する。
- 結果は、画面の状態の変化で示す。正常に終わったことを毎回知らせない。派手な演出もしない。
- 例外（取り消せない操作・結果が画面に現れない操作）は、SKILL.md の規則1・2に従う。

## G-4 最低限のこと以外は、後で決められるようにする

- 始めるのに要る項目だけを必須にし、それ以外は後から設定できるようにする。後で変えられることを画面に書く。
- 権限（通知・位置情報・カメラ）は、まとめて最初に求めず、その機能を使うときに求める。
- 例: 登録時に住所・電話・生年月日まで必須にする → 名前とメールだけで登録させ、ほかは後から入力させる

## G-5 高度な機能は、要るときまで隠しておく

- 初めて使う人が迷わないよう、最初は基本の機能だけを見せる。高度な設定は「詳細設定」「もっと見る」の中に入れる。
- 選択肢が多いときは、基本 → 詳細 → エキスパートと段階に分ける。
- 例: 動画の書き出しで、ビットレートやコーデックを最初から並べる → 「高画質（推奨）/ 標準 / 高速」だけを見せ、細かい設定は詳細設定に入れる
