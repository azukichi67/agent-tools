# スキルを作る・見直す

`.claude/skills/` にスキルを新しく作るか、既存のスキルを設計原則に沿って書き直す。コミットは扱わない（`create-commit` を使う）。スキルの動作を評価するテストは扱わない（必要なら `anthropic-skills:skill-creator` を使う）。

## 手順

### 1. 目的を確かめる

`$ARGUMENTS` から、新規作成か見直しかを判断する。無ければユーザーに確認する。

- 新規作成: スキルに何をさせたいか、いつ使うか、何を入力にして何を出力するかを確かめる。分からない点はユーザーに聞く。
- 見直し: 対象のスキルのディレクトリにあるファイルを全て読む。

スキルの目的を「〜と〜」で繋がない1文で書けたら終わり。

### 2. 責務を決める

`references/design-principles.md` を読む。

- 1文の目的に入らない処理を切り出し、別のスキル・hooks・`.claude/rules/`・`CLAUDE.md`・スクリプトのどこに置くかを決める（原則1）。
- `.claude/skills/` の既存スキルの description を読み、役割が重なるものがあれば、新しく作らずにそのスキルを直す案に変える。
- 見直しの場合は、対象スキルの節ごとに、原則1〜6に反している箇所を書き出す。

切り出すものと置き場所、見直しなら問題点と直し方をユーザーに示し、合意を得たら終わり。

### 3. 振る舞いとナレッジに分ける

中身を、`SKILL.md` に置く手順（振る舞い）と、`references/` に置く観点・規約・例（ナレッジ）に振り分ける（原則2）。

- ナレッジは、変わるきっかけが同じものごとに1ファイルにまとめる。
- 各ファイルを、手順に読むステップとして書くか、条件付きの参照にするかを決める（原則3）。

中身の全ての項目に置き場所が決まったら終わり。

### 4. 書く

`references/repo-conventions.md` を読み、規約に沿って `SKILL.md` と `references/` などを書く。見直しの場合は、手順3で決めた構成に書き換え、手順2でユーザーと合意したもの以外の動作はそのまま保つ。

### 5. 周辺を更新する

- 新規作成なら、`README.md` の「スキルを使う場面」に1行足す。
- 他のスキルから呼ばせるなら、呼び出し元の `SKILL.md` に呼び出す手順を足す。
- 名前や役割を変えたなら、`.claude/skills/` と `README.md` からそのスキルを指している箇所を探して直す。

### 6. 確かめて報告する

次を全て満たすまで直す。

- [ ] 目的を「〜と〜」で繋がない1文で言える
- [ ] `SKILL.md` に観点や知識の一覧が無く、手順だけが書いてある
- [ ] `references/` の各ファイルが、手順の中で読まれるか、読む条件付きで参照されている
- [ ] 目的が特定のツールに依存しない限り、ツール名やコマンドではなく目的が書いてある
- [ ] 各手順の終わりが、終わったと確かめられる条件になっている
- [ ] description が、使う場面を先頭に書いている
- [ ] frontmatter・本文の構成・文体が `references/repo-conventions.md` に沿っている

作った・変えたファイルの一覧と、手順2で切り出したもの（置き場所付き）を報告する。
