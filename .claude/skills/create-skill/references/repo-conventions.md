# このリポジトリのスキルの規約

書き始める前に、作るスキルと型（手順系・規約系）が同じ既存スキルを1つ選んで読み、見本にする。手順系なら `create-commit`、規約系なら `code-naming` が短い。

## 置き場所

- `.claude/skills/<name>/SKILL.md` に置く。ディレクトリ名と frontmatter の `name` を同じにする。`name` は「動詞-名詞」か「対象-観点」の kebab-case（`create-commit`・`code-naming`）。
- 補助のファイルは次のディレクトリに置く。
  - `references/`: ナレッジ（観点・規約・用語・例）
  - `scripts/`: 実行するスクリプト
  - `assets/`: 出力に使うテンプレート
- 外部のリポジトリから取り込んだスキルには `LICENSE` を置き、上流のリポジトリとコミット SHA、改変したことを日本語で書いてから、上流のライセンス全文を続ける。上流にライセンスが無いものは取り込まず、`.gitignore` に入れて git 管理外にする。

## 2つの型

スキルは手順系か規約系のどちらかになる。

| 型 | 中身 | 例 |
|---|---|---|
| 手順系 | 決まった作業を順に進める | `create-commit`, `create-pr`, `explain-table` |
| 規約系 | 実装や計画の途中で、何かを決めるときの基準 | `code-naming`, `code-design`, `unit-test-plan` |

## frontmatter

| 項目 | 付けるスキル |
|---|---|
| `name`, `description` | 全て |
| `argument-hint` | 引数を取るスキル。`"<Issue番号>"` のように `<>` で囲む |
| `disable-model-invocation: true` | ユーザーが明示的に呼ぶワークフローだけ（`plan-issue`, `implement-plan`） |
| `metadata.trigger`, `metadata.language: ja` | 規約系。`trigger` には使う場面を「、」で区切って並べる |

`description` の書き方:

- 手順系: 「〜する。」で何をするかを書き、他スキルとの関係を添える。
  - 例: `作業ツリーの変更を 1コミット1目的に分け、Conventional Commits 形式・日本語のメッセージでコミットする。implement-plan・pr-review-loop から呼ばれるほか、単独でも使える。`
- 規約系: 「〜を決めるときに使う。」で始め、核になる原則を1〜2文書き、使う場面で締める。
  - 例: `識別子（変数や関数、メソッド、クラス、型、ファイル）に名前を付けるときに使う。中身を語らない get の濫用をやめ、値をどうやって得るのかを名前で伝える。実装中と、実装計画でメソッド名やクラス名を決めるときの両方で使う。`

## 本文の構成

手順系:

1. `# <動詞で終わるタイトル>` と、扱わない範囲・前提を書いた1段落
2. `## 手順` の下に `### 1. 前提を確かめる` 〜 `### N. 確かめて報告する` と、番号付きの小見出しを並べる。短いスキルは番号付きリストだけでよい
3. 必要なら `## 最重要ルール`・`## トラブルシューティング`・`## 中断からの再開` を足す

引数は「`$ARGUMENTS` から〜を取得する。無ければユーザーに確認する。」と書く。

規約系:

1. `# タイトル` と、なぜ必要かを書いた1段落
2. `## 適用範囲`（または `## このスキルが決める範囲`）
3. `## 〜の手順`
4. `## 規則` の下に `### 1. 〜する` と、命令形の規則名を並べる
5. `## 書き終えたら確かめること`。`- [ ]` のチェックリスト
6. `## 参照ファイル`。`` - `references/x.md` — 中身の説明 `` の形で並べる
7. `## 出典`。URL と書籍名

## 他スキルの参照

- 読んで従わせる: `` `code-comments` Skill（`.claude/skills/code-comments/SKILL.md`）の「コミットログ・PR（Why）」に従う。``
- 呼び出す: `` Skill tool で `create-commit` を呼び出す。`` 引数を渡すときは「args に〜を渡して」と書く。
- 外部プラグインのスキルは名前空間を付ける（`` `mattpocock-skills:grilling` ``）。

## 文体

- 日本語の、だ・である調の短い文で書く。
- 英単語・コード・パスの前後に半角スペースを入れる（`1コミット1目的` のような数字との組み合わせは詰める）。

## README

`README.md` の「スキルを使う場面」節に1行足す。置く場所は次の3つから選ぶ。

- 「Issue から PR までの流れ」: 流れの1ステップになるスキル
- 「実装中や計画中に参照するもの」: 規約系
- 「単独で使うもの」: それ以外

## 配布

`.claude/skills/` は `compose.yml` で開発コンテナの `~/.claude/skills` に読み取り専用でマウントされ、personal スキルとして読み込まれる。ホストで編集すればすぐ反映されるので、配布のための作業は要らない。
